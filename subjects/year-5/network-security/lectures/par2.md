## [1]{.num} مقدمة عن [Access Control Lists (ACLs)]{.en}

::: def
::: label
تعريف
:::

[Access Control Lists (ACLs)]{.en} (قوائم التحكم بالوصول) من الأدوات
الأساسية في أمن الشبكات، تُستخدم لتنفيذ [Packet Filtering]{.en} (تصفية
الحزم) بهدف التحكم في حركة البيانات التي تمر عبر الشبكة وتحديد مساراتها.
:::

### وظائف ACLs الرئيسية

::: {.grid .cols-3}
::: card
#### 🛡️ تعزيز الأمان (Security)

تقليل حجم حركة المرور غير المرغوب فيها، وتقييد وصول المستخدمين والأجهزة
إلى موارد الشبكة.
:::

::: card
#### 🚫 منع التسريب

منع خروج البيانات غير المصرح بها من الشبكة.
:::

::: card
#### ⚔️ تقليل الهجمات

تسهم في تقليل احتمالية [Spoofing]{.en} (انتحال الهوية)
و[Denial-of-Service (DoS)]{.en} (هجمات حجب الخدمة).
:::
:::

::: key
ACLs لا تقتصر على الأمان فقط --- تُستخدم أيضًا في تطبيقات أخرى داخل الشبكة
مثل توفير وصول ديناميكي ومؤقت عبر [Firewall]{.en} (الجدار الناري)، وضبط
تدفق حركة المرور، وحتى فلترة تحديثات بروتوكولات التوجيه.
:::

### لماذا Border Routers و Firewall Routers هي أهم نقاط التطبيق؟

-   [[Border Routers]{.en}]{.term}[الموجهات الطرفية --- نقطة الاتصال مع
    شبكات خارجية مثل الإنترنت]{.ar}
-   [[Firewall Routers]{.en}]{.term}[موجهات الجدار الناري --- أهم نقاط
    تطبيق ACLs لتوفير مستوى أساسي من الأمان]{.ar}

بدون إعداد ACLs على الموجه، تمر جميع الحزم دون أي قيود، مما يشكل خطرًا
أمنيًا كبيرًا. أما مع ACLs، يمكن السماح لجهاز **Host A** بالوصول إلى شبكة
[Human Resources]{.en} بينما يُمنع **Host B** من الوصول لنفس الشبكة ---
وهذا النوع من التحكم الدقيق أساسي في تصميم الشبكات الآمنة، خصوصًا عند
نقاط الربط مع الإنترنت.

## [2]{.num} تسمية القوائم: [Named]{.en} أو [Numbered]{.en}

يجب تعريف كل ACL باسم [(Name)]{.en} أو رقم [(Number)]{.en}، وتختلف صيغة
الأوامر بينهما.

::: def
::: label
الفكرة الأساسية
:::

[Named ACLs]{.en} (القوائم المسماة) توفر مرونة أكبر في الإدارة مقارنة بـ
[Numbered ACLs]{.en} (القوائم المرقمة)، لأنها تسمح بإعطاء اسم ذو معنى
واضح بدلًا من الاعتماد على أرقام غير واضحة، ويمكن إعادة ترتيب العبارات أو
إضافة عبارات جديدة داخلها بسهولة.
:::

### ميزات متقدمة تدعمها Named ACLs فقط

-   [[TCP Flags Filtering]{.en}]{.term}[تصفية الحزم بناءً على إشارات TCP
    مثل SYN وACK --- تساعد في اكتشاف ومنع أنواع من الهجمات]{.ar}
-   [[IP Options Filtering]{.en}]{.term}[تصفية الحزم التي تحتوي خيارات
    IP إضافية (Source Routing - Timestamp - Record Route)]{.ar}
-   [[Noncontiguous Ports]{.en}]{.term}[تحديد منافذ غير متتابعة في نفس
    القاعدة، مثل السماح للمنافذ 80 و443 و22 معًا]{.ar}
-   [[Reflexive Access Lists]{.en}]{.term}[قواعد ديناميكية تسمح بالردود
    فقط على الاتصالات التي بدأت من داخل الشبكة (تفصيل لاحقًا)]{.ar}
-   [حذف الإدخالات بسهولة]{.term}[استخدام `no permit` أو `no deny` لحذف
    قاعدة دون إعادة كتابة القائمة بالكامل]{.ar}

::: key
استثناء مهم: خطوط [vty (Virtual Terminal Lines)]{.en} المستخدمة للتحكم
بالوصول عن بعد (Telnet/SSH) **لا تدعم إلا Numbered ACLs** في الإصدارات
القديمة من Cisco IOS (الإصدارات الحديثة تدعم كلا النوعين).
:::

::: codebox
::: {.line .comment}
// السماح لجهاز 192.168.1.10 فقط بالدخول عبر Telnet/SSH
:::

::: line
access-list 10 permit 192.168.1.10
:::

::: line
line vty 0 4
:::

::: line
access-class 10 in
:::
:::
:::

::: {#standard-extended .section .block}
## [3]{.num} [Standard]{.en} مقابل [Extended]{.en} ACLs

::: {.grid .cols-2}
::: card
#### 🔹 [Standard ACL]{.en}

يفحص فقط [Source IP Address]{.en} (عنوان المصدر). لا يستطيع التحقق من
الوجهة أو البروتوكول أو المنافذ. أبسط وأقل مرونة، وفعّال جدًا عند استخدامه
**قرب الوجهة (destination)**.
:::

::: card
#### 🔸 [Extended ACL]{.en}

يسمح بتصفية دقيقة بناءً على: المصدر، الوجهة، نوع البروتوكول
(TCP/UDP/ICMP)، أرقام المنافذ، ToS، TCP Flags، IP Options، وقيمة TTL.
يُطبّق عادة **قرب المصدر (source)** لتقليل عبء الحركة غير المرغوبة على
الشبكة.
:::
:::

### نطاقات الأرقام (Numbered ACLs)

::: cmp-wrap
  النوع                      نطاق الأرقام
  -------------------------- -----------------------
  [Standard]{.badge .info}   1--99 و 1300--1999
  [Extended]{.badge .info}   100--199 و 2000--2699
:::

في القوائم المسماة (Named)، يُحدَّد النوع مباشرة بكلمة `standard` أو
`extended` داخل الأمر `ip access-list`.

### الحالتان الاستثنائيتان لـ Standard ACL (لا تُفحص فيهما IP كـ \"مصدر\")

::: steps
##### 1. VTY Access Lists (Outbound)

عند التحكم بالدخول إلى جلسة الراوتر نفسه عبر `access-class`، لا يُعامَل
العنوان كمصدر حزمة، بل كـ**هوية الجهاز** الذي يريد الدخول للراوتر.

##### 2. Routing Filters

عند استخدام ACL لفلترة تحديثات بروتوكولات التوجيه (RIP/OSPF/EIGRP)،
يُعامَل العنوان على أنه **شبكة مُعلن عنها** في جدول التوجيه (Routing
Table)، وليس عنوان مصدر حزمة بيانات. الهدف هو التحكم بأي الشبكات يُسمح
لها بالظهور في جدول التوجيه.
:::

::: codebox
::: {.line .comment}
// مثال Routing Filter: منع إعلان شبكة 10.0.0.0 والسماح بالباقي
:::

::: line
access-list 20 deny 10.0.0.0 0.0.0.255
:::

::: line
access-list 20 permit any
:::

::: {.line .comment}
// (in = فلترة التحديثات الداخلة إلى الراوتر)
:::
:::

::: key
**Extended ACL** يُفضَّل تطبيقه بالقرب من المصدر (closer to source) لتقليل
عبء مرور الحزم غير المرغوبة عبر الشبكة كاملة --- بعكس Standard الذي يُفضَّل
قرب الوجهة.
:::
:::

::: {#time-based .section .block}
## [4]{.num} [Time-Based Access Lists]{.en} (القوائم المعتمدة على الوقت)

::: def
::: label
تعريف
:::

ميزة تسمح بتنفيذ ACLs بناءً على الوقت، عبر إنشاء [Time Range]{.en} (نطاق
زمني) يحدد أوقاتًا معينة من اليوم أو الأسبوع، ثم ربطه بقائمة ACL بحيث
تُطبَّق قيود الوقت على تلك القائمة فقط في تلك الأوقات.
:::

قبل هذه الميزة، كانت أوامر ACL فعّالة بشكل دائم بمجرد تطبيقها. يمكن لكل
من القوائم المسماة والمرقمة الإشارة إلى Time Range.

### فوائد Time-Based ACLs

::: {.grid .cols-3}
::: card
#### 🕐 تحكم دقيق بالوصول

السماح بالوصول أثناء ساعات العمل ومنعه خارجها.
:::

::: card
#### 🔒 تعزيز الأمان

تفعيل قيود أمنية في أوقات محددة، مثل منع الوصول للخوادم خارج الدوام.
:::

::: card
#### 📉 تقليل ضغط الشبكة

تقليل بعض أنواع الترافيك (فيديو، تحميلات كبيرة) في أوقات الذروة.
:::

::: card
#### ⭐ تحسين جودة الخدمة

إعطاء أولوية للتطبيقات المهمة في أوقات معينة.
:::

::: card
#### 📋 تقليل رسائل Logging

تسجيل الأحداث في أوقات محددة بدلًا من التسجيل المستمر، مما يسهّل التحليل.
:::
:::

### خطوات تحقيق Time-Based ACL

::: steps
##### 1. تعريف Time Range

باستخدام إحدى الكلمتين:

-   [[absolute]{.en}]{.term}[للتحكم بالوصول لمرة واحدة فقط، من وقت/تاريخ
    بداية إلى وقت/تاريخ نهاية]{.ar}
-   [[periodic]{.en}]{.term}[لتقييد الوصول بشكل متكرر ودوري (كل نهاية
    أسبوع، أيام العمل، كل يوم، من الإثنين للجمعة)]{.ar}

##### 2. إنشاء ACL وربطها بالنطاق الزمني

باستخدام الكلمة المفتاحية `time-range` ضمن كل قاعدة [permit]{.en} أو
[deny]{.en}.

##### 3. تطبيق ACL على واجهة الموجه

يُحدَّد [Router Interface]{.en} المناسب (عادة الأقرب للمصدر) لتطبيق القائمة
عليها.
:::

::: codebox
::: {.line .comment}
// جدول أوامر Time Range
:::

::: line
time-range time-range-name
:::

::: line
absolute \[start time date\] \[end time date\]
:::

::: line
! و/أو
:::

::: line
periodic days-of-the-week hh:mm to \[days-of-the-week\] hh:mm
:::

::: {.line .comment}
// ملاحظة: يُسمح بعبارة absolute واحدة فقط، لكن يمكن تكرار periodic عدة
مرات
:::
:::

مثال تطبيقي: Sectona (منصة إدارة وصول تجارية)

::: inner
توفر ميزة [Time-Based Access]{.en} مضمّنة لتصفية دقيقة لحزم البيانات،
مثال: يمكن لمسؤول الشبكة إعداد سياسة تسمح لفريق الدعم الفني بالوصول
لخادم معين لمدة ساعة واحدة فقط، وبعد انتهاء الوقت يُمنع الوصول تلقائيًا
دون تدخل يدوي.
:::
:::

::: {#dynamic .section .block}
## [5]{.num} [Dynamic Access Control Lists]{.en} (قوائم الوصول الديناميكية)

::: def
::: label
تعريف
:::

تُعرف أيضًا باسم [Lock-and-Key]{.en}، وهي وسيلة لحل مشكلة لا تستطيع ACL
التقليدية حلها بسرعة: بيئات الشبكة التي تشهد تغييرات مستمرة في عناوين IP
الخاصة بالمستخدمين. تُعدّ باستخدام [IP Dynamic Extended Access
Lists]{.en}.
:::

### المشكلة مع ACL التقليدية

::: {.grid .cols-3}
::: card
#### 1️⃣ تحديد عناوين ثابتة

كل تغيّر في IP لمستخدم شرعي يتطلب تعديل ACL يدويًا.
:::

::: card
#### 2️⃣ تغيرات IP المتكررة

استعارة جهاز، استخدام DHCP، أو أخذ جهاز محمول إلى المنزل يغيّر IP
باستمرار.
:::

::: card
#### 3️⃣ مشاكل أمنية وإدارية

التعديل اليدوي قد يسبب ثغرات أمنية أو عبئًا إداريًا كبيرًا في الشبكات
الكبيرة.
:::
:::

### فوائد Dynamic ACL

-   [إدارة ديناميكية]{.term}[تعديل الوصول تلقائيًا بناءً على سياسات أو
    هوية أو جلسة، دون تعديل يدوي لكل تغيّر IP]{.ar}
-   [مصادقة مدمجة]{.term}[تكامل مع أنظمة مثل 802.1x للتحقق من الهوية قبل
    منح الوصول]{.ar}
-   [زيادة الأمان]{.term}[فقط المستخدمون المصرح لهم يصلون للموارد، بغض
    النظر عن تغيّر IP]{.ar}
-   [تسهيل الإدارة]{.term}[تقليل الحاجة للتعديل المستمر على ACL وتقليل
    العبء الإداري]{.ar}

### كيف تعمل تقنية [Key-and-Lock]{.en} --- خطوة بخطوة

::: steps
##### 1. بدء جلسة Telnet

المستخدم يحاول الوصول عبر بروتوكول Telnet إلى منفذ [VTY (Virtual
Terminal port)]{.en}. هذه الجلسة لا تمنح صلاحية مرور مباشرة، بل تفتح
قناة للمصادقة فقط.

##### 2. المصادقة (Authentication)

يتولى Cisco IOS فتح الجلسة، طلب كلمة المرور، والتحقق من الهوية --- إما
داخليًا عبر الراوتر، أو خارجيًا عبر [TACACS+]{.en} أو [RADIUS]{.en}.
النجاح يمنح صلاحيات مؤقتة، والفشل يُمنع من الوصول.

##### 3. إنشاء إذن مؤقت (Temporary Access)

تُنهى جلسة Telnet تلقائيًا، ويُضاف إدخال مؤقت في Dynamic Access List يحدد
نطاق الوصول المسموح.

##### 4. تبادل البيانات (Data Exchange)

يمكن للمستخدم الآن تبادل البيانات وفقًا للقيود المؤقتة الموضوعة في
الإدخال الديناميكي.

##### 5. انتهاء الإذن المؤقت (Access Expiration)

يُلغى الإذن تلقائيًا بعد [Idle Timeout]{.en} (مهلة خمول) أو [Absolute
Timeout]{.en} (مهلة مطلقة)، أو يدويًا من قبل المسؤول.
:::

::: key
يجب تعيين مهلة واحدة على الأقل (Idle أو Absolute)، وإلا بقيت الإدخالات
المؤقتة فعّالة إلى أجل غير مسمى. إذا استُخدمت المهلتان معًا، يجب أن تكون
قيمة **Idle Timeout أقل من Absolute Timeout**. يمكن تمديد المهلة المطلقة
6 دقائق إضافية عبر أمر `access-list dynamic-extend`.
:::

### خطر الانتحال: [Risk of Spoofing with Lock-and-Key]{.en}

أثناء فتح المنفذ المؤقت، يمكن لمهاجم انتحال عنوان IP للمستخدم الشرعي.
المشكلة ليست في Lock-and-Key نفسها، بل في اعتماد النظام على IP لتحديد
الهوية. **الحل:** يجب تشفير الاتصال بين الجهاز البعيد والموجّه، لأن
المخترق لا يملك مفاتيح التشفير والمصادقة السرية، فلا يستطيع الوصول حتى
لو انتحل IP.
:::

::: {#reflexive .section .block}
## [6]{.num} [Reflexive Access Lists]{.en} (القوائم الانعكاسية)

::: def
::: label
تعريف
:::

نوع من ACLs يسمح بمرور حركة البيانات [(IP traffic)]{.en} التي تنشأ من
داخل الشبكة، لكنه **يرفض أي حركة قادمة من الخارج** إلا إذا كانت تابعة
لجلسة تم إنشاؤها مسبقًا من الداخل.
:::

عند بدء جلسة (مثل اتصال TCP) من داخل الشبكة، تُنشئ القائمة الانعكاسية
مدخلًا مؤقتًا في الـ ACL يسمح بعودة بيانات تلك الجلسة فقط، ويُحذف تلقائيًا
عند انتهائها.

::: key
Reflexive ACLs لا تُطبَّق مباشرة على واجهة الموجه، بل يتم تضمينها
**(Nested)** داخل [Extended Named IP Access List]{.en}. تُعرَّف فقط
باستخدام القوائم الممتدة المسماة --- لا تعمل مع القوائم المرقمة أو
القياسية أو بروتوكولات أخرى.
:::

### Reflexive ACL مقابل الكلمة [established]{.en}

يمكن محاكاة تصفية بسيطة للجلسات في ACL التقليدية عبر
`permit ... established`، التي تفحص وجود بت [ACK]{.en} أو [RST]{.en} (أي
أن الحزمة ليست الأولى في الجلسة). لكن هذا الأسلوب:

-   [established]{.term}[يعتمد فقط على بتّي ACK/RST، يعمل فقط مع TCP،
    ويُطبَّق بشكل دائم على الواجهة]{.ar}
-   [Reflexive ACL]{.term}[يفحص عدة معايير (المصدر، الوجهة، المنافذ)،
    يصعب خداعه (spoofing)، ويعتمد على إدخالات مؤقتة تُحذف تلقائيًا]{.ar}

مشكلة established: لا يمكن استخدامها مع UDP أو ICMP لأنها لا تحتوي أعلام
مشابهة، مما يجبر الإدارة على السماح بكل الحركة أو تعريف كل الأزواج
الممكنة يدويًا (غير عملي ويستهلك ذاكرة NVRAM).

### حذف الإدخالات المؤقتة

::: {.grid .cols-2}
::: card
#### 🔹 بروتوكول TCP (session-based)

**نهاية طبيعية:** عند اكتشاف FIN bit من الطرفين، يُنتظر 5 ثوانٍ ثم يُحذف
الإدخال.\
**نهاية مفاجئة:** عند اكتشاف RST bit، يُحذف الإدخال فورًا.\
**لا توجد حزم:** إذا لم تُكتشف حزم لفترة (timeout)، تُعتبر الجلسة منتهية.
:::

::: card
#### 🔸 UDP / ICMP (sessionless)

لا تحتوي على معلومات نهاية جلسة. تُعتبر الجلسة منتهية إذا لم تُشاهد أي
حزمة من نفس الاتصال لفترة [timeout]{.en} محددة.
:::
:::

### اختيار الواجهة: [Internal]{.en} أو [External]{.en}

قبل إعداد Reflexive ACL، يجب تحديد ما إذا كانت ستُطبَّق على واجهة داخلية أو
خارجية:

::: cmp-wrap
  -------------------------------------------------------------------------
  الحالة            الواجهة           الهدف             الاتجاهات
  ----------------- ----------------- ----------------- -------------------
  [External         مثل Serial 1      منع دخول IP       [Outbound]{.badge
  Interface]{.en}   (متصلة بالإنترنت) traffic إلى       .info} = تسجيل
                                      الجهاز والشبكة    الجلسة (reflect)\
                                      الداخلية ما لم    [Inbound]{.badge
                                      يكن جزءًا من جلسة  .info} = السماح
                                      بدأت من الداخل    بالرد (evaluate)

  [Internal         مثل Ethernet 0    السماح لحركة      [Inbound]{.badge
  Interface]{.en}   (متصلة بالشبكة    خارجية (إنترنت)   .info} = تسجيل
                    المحلية)          بالوصول لخدمات    الجلسة (reflect)\
                                      DMZ (DNS, Web     [Outbound]{.badge
                                      Server) مع منع    .info} = السماح
                                      الوصول للشبكة     بالرد (evaluate)
                                      الداخلية الخاصة   
                                      إلا برد على جلسة  
                                      داخلية            
  -------------------------------------------------------------------------
:::

::: key
القاعدة الذهبية: **حيث تدخل الجلسة الجديدة (reflect)** تُسجَّل، و**حيث يخرج
الرد (evaluate)** يُسمح به. على الواجهة الداخلية: الجلسة تبدأ Inbound (من
المستخدم للراوتر)، والرد يخرج Outbound. على الواجهة الخارجية: العكس
تمامًا.
:::

### المهام الثلاثة الأساسية لإعداد Reflexive ACL

::: steps
##### 1. تعريف Reflexive ACL باستخدام `reflect`

ضمن قائمة IP ممتدة مسماة، على الاتجاه الذي تدخل منه الجلسة الجديدة.

##### 2. تضمين (Nesting) القائمة باستخدام `evaluate`

داخل قائمة IP ممتدة مسماة أخرى، على الاتجاه المعاكس، للسماح بعودة الردود
المطابقة فقط.

##### 3. ضبط Global Timeout Value

القيمة الافتراضية: **300 ثانية**. يمكن تحديد مهلة خاصة لكل ACL، وإلا
استُخدمت القيمة العامة.
:::

::: codebox
::: {.line .comment}
// reflect = تسجيل الاتصال الصادر مؤقتًا
:::

::: {.line .comment}
// evaluate = السماح بعودة الرد المرتبط فقط
:::

::: {.line .comment}
// مثال مفهومي (وليس أمرًا حرفيًا من الشرائح):
:::

::: line
ip access-list extended OUTBOUND
:::

::: line
permit tcp any any reflect TCP_TRAFFIC
:::

::: line
ip access-list extended INBOUND
:::

::: line
evaluate TCP_TRAFFIC
:::
:::
:::
